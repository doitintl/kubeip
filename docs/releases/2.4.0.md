# KubeIP 2.4.0

## Features

- Optional legacy `kubip_assigned` Node label, with changes limited to that key (#126).
- Optional Prometheus assignment metrics, reservation inventory, and health/readiness endpoints (#147).
- Optional GCP drift repair that restores the persisted reservation and refuses to take an address attached elsewhere (#150).
- Separate completion taint with durable success/exhaustion state, preventing repeated address changes after completion (#156).
- AWS public IPv4 IPAM allocation with ownership tags, durable intent, restart recovery and owned-allocation release (#166).

## Reliability

- Retry transient GCP operation-status read failures without repeating cloud mutations.
- Correct the address filter used to recover persisted GCP reservations.
- Retry AWS release when disassociation has not yet become visible to ReleaseAddress.
- Recover IPAM assignments on primary interfaces without a preexisting public IP.
- Include Lease update permission for renewal during longer operations.

## Deployment

New features default off. Node labels, IPAM and persistent state require Node patch permission. Persistent assignment modes require `RELEASE_ON_EXIT=false`; completion cannot be combined with drift repair or IPAM. IPAM requires empty filters, the documented IAM permissions, and API connectivity independent of the managed public IP.

Use Helm chart 0.3.0, which defaults to agent 2.4.0 and allows 330 seconds for shutdown. See the [AWS IPAM guide](../aws-ipam.md), [lifecycle guide](../lifecycle.md), and [v1 migration guide](../v1-migration.md).

The label-loss report #154 remains open pending confirmation of its cause. This release does not claim a reproduced v2 fix for that issue.

Validation included race-enabled Go tests, lint, both container architectures, Helm rendering, and live GCP/AWS assignment, recovery, ownership and release scenarios.
